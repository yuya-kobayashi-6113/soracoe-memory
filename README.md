# soracoe-memory

「Soracoe システム開発」案件（ソーラーパネル施工業務管理システム **SolaCoe**）の**判断の蓄積＝記憶**を置くリポジトリです。

このリポジトリには**コードは入りません**。入っているのは「なぜそう決めたか」「何を試して駄目だったか」「どこに落とし穴があるか」だけです。

## なぜ分けているか

記憶が Cowork のプロジェクトドキュメントにあると、**Mac の Claude Code から読めません**。同じ案件なのに、どこから作業を始めたかで前提が変わってしまいます。

Git に置けば、Cowork からも Mac からも同じものを読めます。差分も履歴も残ります。

## 構成

```
soracoe-memory/
├── README.md          このファイル
├── CLAUDE.md          索引。セッション開始時に読まれる
└── memory/            トピック別。索引を読んで、必要になったものだけ開く
    ├── solacoe.md            案件の現在地と、確立した進め方
    ├── decisions.md          蒸し返されやすい決定と、却下案がどこにあるか
    ├── tech_stack.md         実機で確かめた技術の罠。この環境でできる検証・できない検証
    ├── customer_answers.md   顧客に聞かれたら即答する用
    ├── spec_hazards.md       設計書の落とし穴
    ├── repos.md              GitHub リポジトリまわりの事故の履歴
    └── terminology.md        用語の罠
```

## 3 つの正本の使い分け

混同すると事故ります。

| 何が | どこが正本か |
|---|---|
| **記憶**（判断の蓄積・過去の失敗・環境の癖） | **このリポジトリ** |
| **設計**（詳細設計書・ADR・実装計画） | コードリポジトリ `allsmile-inc/sola-coe` の `docs/` |
| **進め方の共通ルール**（報告の型・メモリ運用・迎合禁止・指示書の型） | `allsmile-ops` プラグインのスキル |

**このリポジトリに設計書を複製しないでください。**古くなった写しが増えるだけです。

Cowork のプロジェクトドキュメント側（`claude/` 配下）にある同じ内容は、**移設時点の写しです。更新しないでください。**

## Mac の Claude Code から読む設定

`~/.claude/settings.json` に次の 2 つのキーを足します（**既存の内容は消さないこと**）。

```json
{
  "permissions": {
    "additionalDirectories": [
      "/Users/<ユーザー名>/path/to/soracoe-memory"
    ]
  },
  "env": {
    "CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD": "1"
  }
}
```

デスクトップアプリの Code タブから起動する場合、`--add-dir` フラグも `~/.zshrc` の環境変数も効きません。GUI アプリはログインシェルの環境変数を（PATH などを除いて）引き継がないためです。上の 2 キーがその代わりになります。

ユーザー設定に置くので、**どのリポジトリを開いても記憶が付いてきます。**

### やってはいけないこと

**複数のリポジトリをまとめた親フォルダを開かないこと。** セッションのルートが親フォルダになり、各リポジトリの `.claude/settings.json` が読まれず、ガードレールが効かなくなります。**1 リポジトリ 1 セッション**が基本です。

### 効いているかの確かめ方

Code タブでコードリポジトリを開き、「いまこの案件で次にやることは何ですか」と聞きます。記憶を踏まえた答えが返れば成功です。目の前のコードの話しかできなければ、パスと設定を見直してください。

## 書くときの原則

- **数字・本数・オープン PR の有無を書かない。**書いた瞬間から古くなります。「どこを見れば数えられるか」だけを書いてください
- **方針が変わったら、同じ作業の中で古い記述を消す。**両方残すと、次に読む人がどちらを信じるか分かりません
- **設計書の内容を写さない。**参照先だけ書いてください
