# 設計書の落とし穴(2026-08-05 S0で実証)

設計書は `docs/detailed-design/`(00〜26章)。**顧客承認済みの `design/` 配下とは別物**で、こちらは編集可。

## 1. 「前版(PostgreSQL版)参照」の前版が存在しない
03章は自身が v1.0 → v2.0 の置き換えで、**v1.0は上書きされている**。「前版参照」と書かれた14テーブルの正準ソースは失われていた。

**ただし14件中13件は、23章データ辞書・09章・08章・05章に項目定義が残っていた。**ゼロから起こす必要があったのは1件だけ。**「参照先が無い」で止まらず、他章を当たること。**

## 2. 他DB・他クラウド前提の残骸が紛れている
**MySQL・AWSで成立するかを毎回確かめる。**実際に踏んだもの: `[Timestamp] byte[]`(SQL Server専用) / `EF.Functions.ILike`(PostgreSQL専用) / 20章 §9.1 のCI定義に `POSTGRES_PASSWORD`・ポート5432 / 21章 §8.3 のロールバックが Azure の `az webapp` のまま / 21章 §6.2 が Azure Key Vault、§7 が Application Insights。

## 3. 05章は多くのエンドポイントでリクエスト/レスポンスを定義していない
取引先(§11)は**17本中16本に定義が無かった**。項目定義の実質的な正準は**各画面章(07〜13章)と23章データ辞書**。

## 4. 同一章内・章間の矛盾が常態
01章 §3.3と§4.3でOwnerの位置づけが矛盾 / 01章 §3.4は見出しだけで本文が空 / 05章 §3.5と§19.1が正反対 / 03章 §3.1の「全テーブル共通の監査列」は実態と乖離 / `PostingType` が03章=3値・23章/09章=4値(DDLが誤り) / `partners.status` が03章=2値・他3章=3値(DDLが誤り)。

## 5. 記述と実装可能性の乖離
「全集約ルートに `RowVersion` 必須」と書いてあるのにDDLに0件 / `materialSalesRepresentative` が検索クエリとデータ辞書に出るのにDDLにもC#モデルにも列が無い / 担当者情報(`contacts`)は画面定義があるのにAPIもDBテーブルも存在しない。

## やり方
- **数値(件数・本数)は必ず数え直す。**「20本以上」と書かれたPUTは実際37本、「54テーブル」のうちDDLがあるのは40だった
- 矛盾は `SPEC_INCONSISTENCIES.md` に記録し、直したら✅を付ける
- 判断が必要なものは `OPEN_QUESTIONS.md` にTBD番号付きで積む
