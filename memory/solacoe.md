## 動く土台の現状(main)

`frontend/` は **Next 16 / React 19 / Tailwind 4(CSS-first) / ESLint 9 Flat Config / pnpm**、`backend/` は **.NET 10 の5プロジェクト**。`dotnet build` / `pnpm build` / `pnpm lint` / `prettier --check` が緑。**この実行環境で全部再現できる**(→[[tech-stack-hazards]] 末尾)。

**依存方向**: `Api → Application → Domain ← Infrastructure` に加え、**`Api → Infrastructure` と `Infrastructure → Application` を張ってある**(2026-08-19 小林さん判断)。前者は**起動時のDI登録(合成ルート)のためだけ**で、**Api のコードから Infrastructure の型を使ってよいという意味ではない**。その禁止は **S1-25 のアーキテクチャテスト**で担保する。

## 大きいファイルを壊さずに書き換える手順(有効。破損0件を維持中)
1. 取得原文を保存し、**git blob SHA が GitHub の値と一致すること**を確認(取りこぼしゼロの確認)
2. **Python の文字列置換で編集**(目視の書き写しをしない)。各置換で出現回数を assert
3. push 後に取り直し、**blob SHA が手元の編集後ファイルと一致すること**を確認

**サブエージェントを並列で走らせるときは一時ファイル名を担当ごとに分ける。**

## 【環境の限界】ロックファイルは GitHub MCP では投入できない
`package-lock.json`(232KB)も `pnpm-lock.yaml`(142KB)も**ツールの出力上限を超えて push できない**(2回とも実測)。**ローカルの git 経路で入れてもらう。**壊れた状態で載せるより無いほうがマシ、という判断で毎回見送っている。

**Docker コンテナ内からパッケージレジストリに到達できない**のもこの環境の限界(実測)。Dockerfile の検証は S1-04 か S9 に回している。
